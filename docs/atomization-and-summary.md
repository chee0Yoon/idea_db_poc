# 원자화와 요약 임베딩

원자는 가장 짧은 문장이 아니라 **조건·예외를 포함해 독립적으로 판단하고 교체할 수 있는 주장**이다. 요약은 그 주장을 찾기 위한 보조 표현이며, 원문이나 목표 적합성 판단을 대신하지 않는다.

예를 들어 “로그인 5회 실패 시 30분 잠금. 관리자는 제외”에서 예외를 떨어뜨려 저장하면 일반 규칙만 재사용될 수 있다. 두 내용을 하나의 원자에 유지한다. FE의 잠금 안내와 BE의 잠금 집행은 독립적으로 변경할 수 있으므로 별도 Idea로 만들고 공통 정책과 연결한다. “빠르게 처리한다”처럼 기준이 불명확하면 임의 숫자를 채우지 않고 Candidate에 남긴다.

## 저장·검색 구조

| 층 | 내용 | 처리 |
|---|---|---|
| Capture | 원문 전문, 발생 시각, 출처 | 먼저 MCP로 보존 |
| Revision.body | 주체·행동·조건·예외·수치/단위가 있는 완전한 주장 | 출처 추출과 추론 구분, 불변 |
| Revision.summary | 같은 출처에 근거한 AI 요약·지시어 해소·검색 동의어 | 본문과 별도 출처 표시, 클라이언트 검토 |
| 구성/사용 위치 | Project → Schema → Core* → Idea, root/path, R&R | 공유 Idea 자체에 부모 목표를 넣지 않음 |
| Goal/Baseline | 해당 사용 위치의 목표와 채택 기준 | 요약의 내용이나 유사도로 달성률을 만들지 않음 |
| Embedding | 요약이 있으면 요약 + 본문 전체, 없으면 기존 본문 | 로컬 Ollama, 모델 digest·입력 형식·입력 digest 고정 |
| 검색 문맥 | 선택한 사용 위치와 조상의 본문/요약, 범위별 목표 이력 | 검색 뒤 별도 포장, 크기 제한과 잘림 표시 |

로컬 AI는 원문을 보고 원자와 요약을 작성한다. 입력 스킬은 각 원문 요구사항이 Idea, 보류 Candidate, 사유 있는 제외 중 어디에 대응하는지 검토하도록 한다. DB는 생성형 모델을 호출하지 않는다.

```json
{
  "body": "연속 5회 로그인 실패 시 계정을 30분 잠근다. 관리자는 제외한다.",
  "summary": {
    "text": "로그인 잠금 정책: 연속 실패 5회, 잠금 30분, 관리자 예외.",
    "source": {
      "origin": "ai", "claim_mode": "inferred",
      "capture_id": "cap_login_policy", "model": "local-client-model",
      "skill": "idea-db-input", "source_anchor": null
    }
  }
}
```

위 내용은 Revision의 일부이며 본문의 source도 같은 실제 Capture를 참조해야 한다. 요약은 1..2000자다. 임베딩 입력은 정확히 `Summary:\n{summary.text}\n\nBody:\n{body}`이며 `/idea-body-summary-v2`로 구별한다. 본문 조건을 요약에만 남기거나 모델 입력 한도 때문에 본문을 자동 자르지 않는다. 한도 초과는 업로드 실패이며 원문은 보존된다.

preview의 `review_records`에서 본문과 요약을 검토하고 `embedding_inputs`의 입력 digest/프로파일을 확인한 뒤 같은 prepared digest를 적용한다. 출처 형식 검증은 요약의 의미 충실성을 증명하지 못한다. 실제 반대 의미의 요약도 형식이 맞으면 검토 대상으로 준비될 수 있으며, 이를 거절할 책임은 입력 클라이언트의 검토에 있다.

## 공유·과거 기록 처리

기존 Revision/벡터/출처를 소급 변경하지 않는다. 요약이 없는 기록은 `/idea-body-v1`로 계속 검색된다. 요약 추가만을 위해 가짜 본문 교정 이력을 만들지 않는다. 과거 기록에 요약을 덧붙이는 별도 불변 주석 레코드는 이번 범위에 포함하지 않았다.

MCP 검색 기본 `embedding_format: auto`는 같은 모델 digest의 두 입력 형식을 명시적으로 허용한다. 각 결과의 선택 프로파일과 형식별 커버리지를 반환한다. 하나의 Revision에 여러 허용 벡터가 있어도 최고 코사인 점수 하나만 어휘 순위와 결합한다. 다른 모델 digest는 비교하지 않는다. 실험에서는 `body_v1`/`body_summary_v2`를 개별 선택할 수 있다.

공유 원자가 FE와 BE에 나타나면 문맥은 각각의 경로에서 가져온다. 부모의 역할을 자식에서 복사하지 않는다. `goal_history`는 그 경로의 목표 이력이며 현재 목표 선택이 아니다. 활성 기준선/평가는 `idea_goals`에서 확인한다. 과거 지식 시점은 나중에 추가된 목표를 제외한다. occurrence replacement가 복사하는 조상에서는 이전 구성의 요약을 제거한다.

검색 문맥 기본 예산은 MCP에서 JSON Unicode 문자 8000자, HTTP에서 0이다. 이는 토큰 예산이나 응답 전체 크기 제한이 아니다. 가까운 사용 위치부터 포장하고, 큰 본문/요약은 표시용으로 축약한다. `body_truncated`, `summary_truncated`, `goals_truncated`, 전체 `context.truncated`를 확인하고 필요한 경우 원본 record ID로 다시 조회한다. 문맥을 많이 붙이는 것이 항상 유리하지 않으므로 0으로 끌 수 있다. 별도의 사용 위치 벡터 인덱스·자동 문맥 재순위화는 구현하지 않았다.

## 실험과 한계

`tests/summary_ingest.py`는 같은 제목·본문을 가진 6쌍을 만들고, 한쪽에만 요약을 넣는다. 각각 6개 후보로 엄격히 나눈 뒤 동일한 6개 질의를 검색한다. 정답은 사전 지정한 관련 쌍이며 다른 후보를 정답에 포함하지 않는다. 부정 조건·야간 배포·롤백·점검·사고·보존 예외를 포함한다. 1쌍은 지시어가 남은 불완전한 과거 입력의 반례, 나머지는 구체적인 본문과 검색 동의어 요약이다.

2026-09-07 실제 `embeddinggemma:300m` 실행에서 **요약을 포함하는 하이브리드 검색** MRR은 본문 전용 **0.9167**, 요약+본문 **1.0000**, 평균 Recall@3은 **0.9167 → 1.0000**이었다. 어휘 점수에도 요약이 들어가므로 이 숫자만으로 임베딩의 독립적인 효과를 주장하지 않는다. 같은 실행에서 저장한 vector_rank만 별도 집계해도 이번 6개 질문에서는 같은 수치였다. [측정 요약](evidence/20260907-summary-embeddings.json)에 두 집계를 구분했다. 영어 동의어를 넣은 사람이 작성한 합성 요약과 작은 질의 집합의 결과다. 이 결과는 일반 검색 품질, 자동 원자화 능력, 생성 답변 정확도나 목표 달성 향상을 증명하지 않는다.

같은 실행에서 기존 30단계, 39개 문맥 질의, 모델 출력 저장, 새 요약 입력을 포함한 **1,124개 기록·362개 Revision·10개 head·88개 receipt**를 실제 Neo4j에서 검사했다. 재시작/빈 DB 복원 후 동일 export와 무결성을 확인했다. 원문 보존, 잘못된 요약 출처 거절, 입력 digest, 이전 프로파일 검색, 공유 경로와 나중 목표의 과거 조회 제외도 검증했다. 명령은 `make evidence-check`이며 성공·실패 로그는 지우지 않는다.

기존 실험의 부정/비교 연산자 의미 변경을 완벽히 판별하지 못하는 한계는 남아 있다. 요약이 이 문제를 해결한 것처럼 표시하지 않는다. [앞선 원자화·문맥 실험](context-evidence.md)과 함께 해석한다.
