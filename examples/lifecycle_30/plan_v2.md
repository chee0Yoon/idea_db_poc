# AI 운영 장애 분석·대응 지원 제품 계획 v2

## 전환 배경

고객 문의 자동화보다 내부 운영 장애의 탐지·분석·복구 의사결정이 더 시급해졌다. 기본 개념인 “AI가 자료를 모아 제안하고 사람이 채택한다”는 유지하지만, 사용자는 상담원이 아니라 온콜 엔지니어이며 입력은 문의가 아니라 경보·로그·배포 변경이다. 결과도 답변 초안이 아니라 장애 가설, 영향 범위, 실행 가능한 대응 절차다.

## 제품 목표

- 경보 발생 후 2분 안에 관련 신호와 최근 변경을 한 타임라인으로 묶는다.
- 근거가 없는 원인 단정과 자동 복구 실행을 허용하지 않는다.
- 온콜 담당자가 채택한 가설, 기각한 가설, 조치 결과를 불변 이력으로 남긴다.
- 늦게 도착한 로그의 실제 발생 시각과 시스템이 알게 된 시각을 모두 보존한다.
- 서비스별 소유권이 달라도 공통 승인·감사·복구 원칙은 같은 Idea Revision으로 재사용한다.

## 역할별 실행 계획

### FE

1. `fe_1`: 경보, 로그, 배포 변경, 가설을 하나의 사고 타임라인에 표시한다.
2. `fe_2`: 대응 명령의 위험도·근거·승인 상태를 검토하는 화면을 제공한다.
3. `fe_3`: 현재 장애와 과거 유사 장애의 차이와 공통점을 분리해 보여준다.

### BE

1. `be_1`: 경보 공급자의 중복 이벤트를 멱등 수집하고 원문을 보존한다.
2. `be_2`: 장애 가설·근거·조치의 상태 전이와 승인을 강제한다.
3. `be_3`: 실행 어댑터는 승인된 런북 단계만 수행하고 결과를 다시 기록한다.

### Infra

1. `infra_1`: 서비스 상태, 포화도, 오류 예산, 의존성 신호를 수집한다.
2. `infra_2`: 대응 권한과 비밀값을 서비스·환경별로 격리한다.
3. `infra_3`: 저장소·API 장애 중에도 사건을 잃지 않는 복구 절차를 검증한다.

### ML

1. `ml_1`: 경보 묶음의 중복률과 사건 단위 군집 정확도를 측정한다.
2. `ml_2`: 가설 순위가 실제 원인과 얼마나 일치하는지 오프라인 평가한다.
3. `ml_3`: 서비스별 관측 편향과 드문 장애의 누락률을 분석한다.

### DL

1. `dl_1`: 로그·트레이스 표현 모델의 버전별 검색 품질을 평가한다.
2. `dl_2`: 긴 시간 구간과 다중 서비스 문맥을 잃지 않는지 점검한다.
3. `dl_3`: 추론 지연, GPU 메모리, 입력 길이 제한을 재현 가능하게 측정한다.

### LLM

1. `llm_1`: 근거 ID를 동반한 장애 가설만 출력하는 구조화 계약을 사용한다.
2. `llm_2`: 위험한 조치는 제안 단계에 고정하고 사람 승인을 요구한다.
3. `llm_3`: 고정된 장애 픽스처로 가설·요약·런북 회귀를 실행한다.

## 재사용과 파생

사람 승인 원칙과 불변 감사 기록은 v1의 정확한 Idea Revision을 재사용한다. 고객 답변이라는 문맥을 가진 Idea는 그대로 쓰지 않고 운영 조치 문맥의 새 Entity로 의미 파생한다. 파생 관계는 의미 연속성을 나타낼 뿐, 과거 목표·평가·근거를 새 사용 위치에 자동 승계하지 않는다.

## 관측과 평가

각 역할의 실행기는 실제 파일을 만들고 그 파일을 다시 읽어 상태·측정값·해시를 반환한다. LLM 역할은 외부 호출 없이 고정 어댑터 픽스처를 실행한다. 각 관측은 코드 참조, 데이터 버전, 모델 버전, 설정 해시, 런타임을 기록한다. 목표와 기준선은 현재 루트, 슬롯 경로, 대상 Revision을 정확히 고정한다.

### 이번 검증의 제한된 실행 범위

아래 실행은 역할별 원자의 저장·근거·시간·검색 연결을 검증하는 작은 기술 프로토타입이다. 장애 분석 제품 기능의 구현 완료나 품질을 뜻하지 않는다.

| 작업 | 실제 실행 지표 | 제한된 검증 대상 |
|---|---|---|
| `fe_1` | `escaped_card_count` | 신뢰할 수 없는 카드 제목 이스케이프 |
| `fe_2` | `visible_role_records` | 고정 배열의 역할 필터 |
| `fe_3` | `serialized_timeline_events` | RFC3339 정렬과 JSON 왕복 |
| `be_1` | `rejected_invalid_payloads` | 허용 필드 기반 입력 검사 |
| `be_2` | `idempotency_replays` | 메모리 안의 멱등 상태 전이 |
| `be_3` | `stale_cas_rejections` | 단일 프로세스 CAS 상태 전이 |
| `infra_1` | `atomic_round_trips` | 임시 파일 fsync·교체·재조회 |
| `infra_2` | `persisted_secret_values` | 비밀값 없는 고정 설정 검사 |
| `infra_3` | `restart_manifest_fields` | 재시작 manifest 직렬화 |
| `ml_1` | `holdout_accuracy` | 합성 선형 데이터 분류 |
| `ml_2` | `feature_mean_shift` | 합성 특징 평균 이동 |
| `ml_3` | `untouched_test_recalibrated_brier_score` | 분리된 test 확률 보정 평가 |
| `dl_1` | `xor_holdout_accuracy` | 작은 CPU MLP XOR 평가 |
| `dl_2` | `non_finite_inputs_rejected` | 비유한 입력 거절 |
| `dl_3` | `changed_input_accuracy_degradation` | 합성 입력 이동 성능 변화 |
| `llm_1` | `prompt_instruction_words` | 고정 프롬프트 수정 픽스처 |
| `llm_2` | `valid_structured_responses` | 구조화 응답 스키마 검사 |
| `llm_3` | `unsupported_citations_blocked` | 고정 근거 ID 허용 목록 |

각 공식 평가는 이 표의 실제 측정 지표 하나만 판단한다. 상위 제품 목표나 역할 전체의 완료 여부를 원자 실행 결과에서 추론하지 않는다.

## 출시 조건

내부 섀도 모드에서 제안만 생성한다. 자동 명령 실행은 범위 밖이다. 필수 기준을 충족한 공식 평가, 복원 시험, 과거 시점 누수 방지, 역할 필터 검색이 확인된 뒤 온콜 보조 화면을 연다.

## 주요 위험

- 상관관계를 원인으로 오해: 유사도·영향·지지 관계를 구분한다.
- 늦은 로그로 과거 판단 변조: `occurred_at`과 `recorded_at/seq`를 함께 조회한다.
- 위험한 자동 조치: 승인된 런북과 실행 결과를 분리하고 모든 실패를 보존한다.
- 서비스 간 자료 누출: Project 문맥과 역할 경계를 쿼리에서 강제한다.
