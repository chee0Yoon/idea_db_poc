# AI 고객 문의 분류·초안 지원 제품 계획 v1

## 제품 맥락

고객지원 담당자가 여러 채널에서 들어오는 문의를 빠르게 분류하고, 근거가 있는 답변 초안을 검토한 뒤 발송하도록 돕는다. AI는 분류와 초안을 제안하지만 최종 판단과 발송 책임은 상담원이 가진다. 최초 사용자는 사내 고객지원팀이며, 개인정보와 잘못된 답변의 확산을 막는 것을 처리량보다 우선한다.

## 성공 기준

- 문의가 접수된 뒤 30초 안에 상담원 화면에 분류와 답변 초안이 나타난다.
- 상담원이 승인하지 않은 문장은 외부로 전송되지 않는다.
- 답변의 근거 문서와 버전을 화면과 감사 로그에서 확인할 수 있다.
- 모델 실패 시 원문 문의를 잃지 않고 수동 처리 대기열로 보낸다.
- 역할별 실행 결과를 코드·설정·데이터·모델 버전과 함께 재현할 수 있다.

## 역할별 계획

### FE

1. `fe_1`: 문의 본문, AI 분류, 신뢰 근거를 한 화면에 표시한다.
2. `fe_2`: 상담원이 초안을 수정하고 승인 또는 반려 사유를 남긴다.
3. `fe_3`: 과거 처리 기록과 현재 제안을 시간 순서로 비교한다.

### BE

1. `be_1`: 채널별 문의를 동일한 사건 형식으로 수집하고 멱등 처리한다.
2. `be_2`: 분류·초안·승인 상태 전이를 검증하고 감사 이벤트를 남긴다.
3. `be_3`: 승인된 답변만 채널 어댑터로 전달하고 재시도를 통제한다.

### Infra

1. `infra_1`: API와 저장소의 준비 상태, 지연 시간, 오류율을 수집한다.
2. `infra_2`: 비밀값과 고객 데이터를 분리하고 최소 권한으로 배포한다.
3. `infra_3`: 장애 시 원문과 감사 기록을 보존한 채 복구 절차를 실행한다.

### ML

1. `ml_1`: 문의 의도와 긴급도를 규칙 기반 기준 데이터로 평가한다.
2. `ml_2`: 답변 후보의 근거 일치율과 금지 표현 위반을 측정한다.
3. `ml_3`: 상담원 수정량과 반려 사유를 편향 없이 분석한다.

### DL

1. `dl_1`: 한국어 문의 임베딩과 분류 모델의 고정 버전을 평가한다.
2. `dl_2`: 긴 문의의 문맥 손실과 채널별 분포 이동을 점검한다.
3. `dl_3`: 모델 지연·메모리·배치 크기의 재현 가능한 측정을 남긴다.

### LLM

1. `llm_1`: 검색된 근거만 사용하도록 결정적 프롬프트 계약을 정의한다.
2. `llm_2`: 개인정보와 확정할 수 없는 내용을 초안에서 차단한다.
3. `llm_3`: 승인·반려 사례로 오프라인 회귀 평가를 실행한다.

## 데이터와 근거

문의 원문은 발생 시각과 기록 시각을 분리한다. 실행 결과는 작은 JSON 결과와 그 SHA-256을 보존하고, 큰 파일은 URI·크기·해시만 저장한다. 관측값은 대상 Idea Revision과 정확히 연결하며 실패, 무효, 미관측, 부정 결과를 성공값과 구별한다.

## 의사결정과 출시

1차 출시는 제안 화면과 수동 승인까지만 포함한다. 자동 발송, 온라인 학습, 고객별 모델 튜닝은 제외한다. 역할별 세 개의 실행 점검이 모두 기록되고, 필수 기준에 대한 공식 평가가 근거를 갖춘 뒤에만 내부 파일럿을 연다.

## 위험과 대응

- 잘못된 근거: 근거 버전과 인용 범위를 고정하고 없는 근거는 생성하지 않는다.
- 개인정보 노출: 입력 단계에서 마스킹하고 원문 접근을 감사한다.
- 모델 지연: 제한 시간을 넘기면 수동 처리로 전환한다.
- 평가 누수: 관측 발생 시각 이후의 근거를 과거 평가에 사용하지 않는다.
