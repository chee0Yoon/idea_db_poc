# AI 사내 지식 검토·정비 지원 제품 계획 v3

## 전환 배경

장애 대응 도구에서 얻은 근거 추적과 사람 승인 구조를 사내 지식 품질 관리에 적용한다. 입력은 문서, 정책, 코드 설명, 회의 결정이며 결과는 중복·충돌·노후 정보의 검토 제안이다. 실시간 장애 대응보다 정확한 출처, 문서 소유자 확인, 변경 전후의 설명 가능성이 중요하다.

## 제품 목표

- 새 문서가 들어오면 관련 기존 지식과 충돌 후보를 근거와 함께 제시한다.
- AI가 제안한 통합·폐기·수정은 담당자가 채택하기 전까지 공식 지식에 섞이지 않는다.
- 문서의 발생 시각, 수집 시각, 검토 시각을 분리해 과거 상태를 재현한다.
- 승인·감사·복구처럼 문맥 독립적인 Idea는 기존 Revision을 명시적으로 재사용한다.
- 지식의 최신성, 출처 완전성, 담당자 승인 여부를 각각 평가한다.

## 역할별 계획

### FE

1. `fe_1`: 원문, 관련 문서, 충돌 문장, 제안 변경을 나란히 표시한다.
2. `fe_2`: 소유자가 제안을 채택·수정·반려하고 이유를 기록한다.
3. `fe_3`: 특정 시점의 공식 지식과 이후 정정 내용을 비교한다.

### BE

1. `be_1`: 파일·URL·메모 입력을 사건으로 보존하고 중복 요청을 통제한다.
2. `be_2`: 후보, 검토, 채택, publication의 상태 전이와 권한을 검증한다.
3. `be_3`: 문서 원본과 파생 원자의 출처 앵커 및 해시를 제공한다.

### Infra

1. `infra_1`: 색인 지연, 실패율, 저장소 준비 상태를 관측한다.
2. `infra_2`: 부서별 문서 접근과 모델 전달 범위를 격리한다.
3. `infra_3`: 전체 export, 빈 저장소 import, 재시작 후 조회를 검증한다.

### ML

1. `ml_1`: 중복 후보의 정밀도와 재현율을 담당자 판정으로 측정한다.
2. `ml_2`: 충돌 후보가 실제 정책 모순을 포함하는지 평가한다.
3. `ml_3`: 부서·문서 유형별 누락과 과탐 편향을 분석한다.

### DL

1. `dl_1`: 한국어 문서 임베딩의 버전별 검색 품질을 고정 집합에서 비교한다.
2. `dl_2`: 긴 문서 분할이 인용 범위와 의미를 훼손하지 않는지 점검한다.
3. `dl_3`: 색인·추론 자원과 입력 크기 한계를 기록한다.

### LLM

1. `llm_1`: 출처 문장과 제안 문장을 분리한 구조화 출력만 허용한다.
2. `llm_2`: 불확실한 충돌은 질문으로 남기고 사실처럼 단정하지 않는다.
3. `llm_3`: 고정 문서 픽스처로 요약·충돌 탐지·변경 제안 회귀를 실행한다.

## 정보 모델

Project Revision은 여섯 Schema를 고정하고, 각 Schema는 역할별 Core와 세 개의 원자 Idea를 포함한다. 한 Idea가 여러 위치에서 쓰이면 같은 Revision을 고정하되 역할과 목표는 슬롯 경로에 둔다. 문맥이 바뀐 의미 수정은 새 Entity와 `semantic_edit` 계보로 남긴다.

## 근거와 시간

실행 파일은 URI와 SHA-256을 Artifact로 저장하고 핵심 상태·측정값은 Observation으로 남긴다. 늦게 수집된 과거 문서는 현재 검색에는 나타날 수 있지만 과거 `known_at` 조회에는 나타나지 않아야 한다. `effective_at` 이전에 발생하지 않은 관측은 근거와 공식 달성도에서 제외한다.

## 채택 기준

초기 릴리스는 검토 후보 생성, 관련 지식 검색, 사람 승인, 버전 publication을 포함한다. 자동 삭제와 부서 간 자동 공유는 제외한다. 새로운 “출처 완전성” 목표는 v3의 정확한 사용 위치에 생성하고 이전 제품 문맥의 기준선을 무리하게 supersede하지 않는다.

## 한계와 후속 검증

결정적 텍스트 특징과 한국어 어휘 질의의 Recall@k는 기능 검증에 사용한다. 이는 실제 의미 임베딩 품질을 증명하지 않는다. 실제 부서 문서와 담당자 판정으로 검색 품질, 수정 비용, 권한 모델을 별도 평가한다.
